Data Description

We will be working with data from NHANES, the National Health and Nutrition Examination Survey. NHANES has been run by the CDC since the 1960s. Every two years it interviews a nationally representative sample of about 10,000 Americans, brings them into a mobile examination center for a physical exam, and draws blood. We are using the 2017-2018 cycle, which examined 9,254 people.

The public NHANES files are documented here:

Centers for Disease Control and Prevention (CDC). National Center for Health Statistics (NCHS). National Health and Nutrition Examination Survey Data, 2017-2018. Hyattsville, MD: U.S. Department of Health and Human Services, Centers for Disease Control and Prevention. https://wwwn.cdc.gov/nchs/nhanes/continuousnhanes/default.aspx?BeginYear=2017

The tables we use here were built from those files by data/build_nhanes_data.R in this repository. The tables are already stored in a subdirectory called “data” placed immediately inside the directory containing this notebook. Note that NHANES does not release exam dates or dates of birth, so the exam_start, exam_end, and birth_date columns are simulated (consistent with each participant’s real reported age and examination period). Every measurement, lab value, and drug name is real. In this example, we will be working with participant records stored in participants.csv.

Write Your First Function

Many of the physical measurements in this data set are missing for some participants, because not everyone completed every part of the exam. R takes missing values seriously, so the mean of a column that contains even one NA is itself NA.

Passing the optional argument na.rm = TRUE tells mean to drop the missing values first. That works, but it has to be typed out on every single call.

Repeated code like this is a signal that a function is called for. Writing one gives the operation a name, and it means a later change has to be made in one place instead of three.

TipShow the answer 
# TODO: Write a function called `mean_obs` (short for "mean observed") that takes a vector
# and returns the mean of its non-missing values. Your function should call `mean` internally.
mean_obs <- function(x) {
  mean(x, na.rm = TRUE)
}

Before turning a new function loose on real data, run it on a few inputs whose answer you already know. Tests like these are a critical part of writing code you can trust.

Now that the function is working, the three lines from earlier read more clearly.

Optional Arguments

The means above print with more decimal places than a body mass index deserves. Rather than rounding at every call site, give the function an optional argument. An argument becomes optional when you write = and a default value after its name in the function declaration.

TipShow the answer 
# TODO: Write a new version of `mean_obs` that takes a second, optional argument called `digits`
# with a default value of 1, and rounds the result to that many decimal places
mean_obs <- function(x, digits = 1) {
  round(mean(x, na.rm = TRUE), digits)
}

Callers who leave digits out get the default, and callers who need more precision can ask for it.

Returning Multiple Values

A function can only return one object. When several numbers belong together, gather them into a list and return that single list.

TipShow the answer 
# TODO: Write a function called `describe` that takes a vector and returns a list with three
# named elements:
#   `n_observed`: the number of non-missing values
#   `mean`: the mean of the non-missing values
#   `range`: the smallest and largest non-missing values, as a vector of length two
describe <- function(x) {
  list(
    n_observed = sum(!is.na(x)),
    mean = mean_obs(x),
    range = range(x, na.rm = TRUE)
  )
}

# Describe the body mass index column
describe(df_participant$bmi)

Iterate a Function Over Columns

map takes a list as its first argument and a function as its second, runs the function on every element of the list, and collects the results. A data frame is a list of columns, so mapping over one walks across its columns.

Let’s isolate five continuous measurements to work with.

map itself always returns a list. The variants named after a data type return that type instead, so map_dbl returns a numeric vector, which is easier to read here.

TipShow the answer 
# TODO: Use `map_dbl` to compute `mean_obs` for every column of `vitals`
vitals_means <- vitals %>%
  map_dbl(mean_obs)

# Print the mean of each measurement
print(vitals_means)

Notice that map kept the column names, so you can tell which mean belongs to which measurement.

Anonymous Functions

mean_obs was worth naming because we use it repeatedly. For a calculation used exactly once, you can define the function right inside the call to map. Such a function is called anonymous because it is never assigned a name. The syntax is \(ARGUMENTS) BODY, which is shorthand for function(ARGUMENTS) {BODY}.

Every one of these measurements is missing for at least some participants. Let’s find out how often.

TipShow the answer 
# TODO: Use `map_dbl` with an anonymous function to compute the proportion of values
# that are missing in each column of `vitals`
missing_share <- vitals %>%
  map_dbl(\(x) sum(is.na(x)) / length(x))

# Print the proportion missing for each measurement
print(missing_share)

Pulse, cholesterol, and HDL are missing for roughly a quarter of participants, which limits what you can safely conclude from them.

Build a Summary Table

imap works like map, except the function it calls receives two arguments: the value and its name. That makes it possible to build a result that labels itself. Here we produce one single-row table per measurement and then stack them.

TipShow the answer 
# TODO: Use `imap` to build a one-row tibble for each column of `vitals` containing the
# column name, the number of missing values, and the mean of the observed values,
# then use `bind_rows` to stack the tibbles into a single table
vitals_summary <- vitals %>%
  imap(\(column, name) tibble(
    variable = name,
    n_missing = sum(is.na(column)),
    mean = mean_obs(column)
  )) %>%
  bind_rows()

# Display the summary table
print(vitals_summary)

Simulate a Small Survey

Suppose a researcher wants to know whether most Americans are overweight, and cannot afford to examine 9,254 people. They measure 20 and find that only 9 of them have a body mass index of 25 or higher, so they report that most Americans are not overweight.

Could they be wrong? We happen to have the larger sample, so we can check how often a 20-person study would reach the wrong conclusion.

A slim majority, so the researcher’s conclusion is wrong. To see how easily that happens, write a function that simulates one 20-person study and reports what it would conclude.

TipShow the answer 
# TODO: Write a function called `survey_says` that takes a single argument (which it ignores),
# draws a sample of 20 values from `bmi_observed`, and returns TRUE if more than half of
# that sample is 25 or higher
# Hint: `sample(bmi_observed, 20)` draws the sample
survey_says <- function(i) {
  sample_bmi <- sample(bmi_observed, 20)
  mean(sample_bmi >= 25) > 0.5
}

One study on its own tells us very little, so run 500 of them. Passing 1:500 to map_lgl calls the function 500 times, once per element, which is why survey_says takes an argument it never uses.

TipShow the answer 
# Fix the random number generator so this notebook gives the same answer every time it runs
set.seed(1)

# TODO: Use `map_lgl` to run `survey_says` 500 times
survey_results <- 1:500 %>%
  map_lgl(survey_says)

# TODO: Take the average of `survey_results` to get the share of studies that got the answer right
share_correct <- mean(survey_results)

cat(paste0(round(100 * share_correct, 1), "% of 20-person studies concluded that most people are overweight."))

That is barely better than a coin flip, even though the underlying answer never changed. A 20-person study is too small to settle a question this close.

Vary the Sample Size

A larger study should do better. Rewrite the function so the sample size is an argument rather than a hard-coded 20.

TipShow the answer 
# TODO: Write a function called `survey_says_n` that takes the sample size `n` as its argument
# and otherwise behaves like `survey_says`
survey_says_n <- function(n) {
  sample_bmi <- sample(bmi_observed, n)
  mean(sample_bmi >= 25) > 0.5
}

expand_grid returns every combination of the values you hand it, so the table below has one row per study: 500 repetitions at each of three sample sizes.

pmap walks along several inputs in parallel, handing the function one value from each. Given a data frame it uses the columns, matching them to the argument names of the function you supply.

TipShow the answer 
set.seed(1)

# TODO: Use `pmap_lgl` to run one study per row of `settings`
# Hint: the anonymous function receives both `n` and `rep`, but only needs `n`
correct <- settings %>%
  pmap_lgl(\(n, rep) survey_says_n(n))

# Attach the results to the settings they came from
results <- settings %>%
  mutate(correct = correct)

# TODO: Group `results` by sample size and compute the share of studies that got the answer right
share_by_n <- results %>%
  group_by(n) %>%
  summarise(share_correct = mean(correct))

# Print the share correct at each sample size
print(share_by_n)

Summary

Writing a function gives a piece of work a name, a single place to fix, and something you can test on inputs whose answers you already know. Once the work is packaged that way, map and its relatives let you run it across a whole list without copying anything. In this notebook we wrote mean_obs and gave it an optional argument, returned several values at once from describe, mapped across the columns of a data frame to summarize five measurements, and simulated 2,000 studies to show that a 20-person survey of a 54.5% majority reaches the right conclusion only a little more often than a coin flip.
